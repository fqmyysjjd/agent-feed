# Agent Feed CLI Product Plan

Date: 2026-04-30

## Purpose

This document records the product-grade CLI design for Agent Feed and the current command boundary. It started as a pre-implementation plan; now it also tracks which command responsibilities are implemented and which boundaries still need review before a stable release.

## Outcome Boundary

The next implementation should stop when Agent Feed has:

1. A polished interactive CLI with keyboard multi-select for clients and checks.
2. A deterministic non-interactive CLI for scripting and CI.
3. Correct adapter behavior for Codex, Claude Code, and Cursor.
4. A clearer internal package structure instead of one large `cli.py`.
5. Tests or smoke checks for init, sync, check, status, skill-hub, and dry-run behavior.

Out of scope for the next implementation:

1. Brownfield automatic migration of existing AI instruction assets.
2. Destructive pruning during upgrade of previously initialized projects.
3. Framework-specific or monorepo verification profiles beyond the current built-in presets.
4. Organization/team remote template registry.
5. CI integration package or GitHub Action.

## Research Findings

### Codex

Codex uses `AGENTS.md` for repository-level instructions. Codex also reads repository skills from `.agents/skills` from the current working directory upward to the repository root.

Design implication:

1. `AGENTS.md` and `.agents/skills` are already native Codex assets.
2. Agent Feed should not create `.codex/skills` as the default project mirror.
3. `.codex` should be treated as Codex-specific home/config territory unless a future Codex project-local convention becomes official.

Sources:

1. https://developers.openai.com/codex/guides/agents-md
2. https://developers.openai.com/codex/skills

### Claude Code

Claude Code reads `CLAUDE.md`, not `AGENTS.md`. Claude docs recommend creating `CLAUDE.md` with `@AGENTS.md` when a repository already uses `AGENTS.md`, so both tools share the same instructions without duplication. Claude project skills live under `.claude/skills/<skill-name>/SKILL.md`.

Design implication:

1. `AGENTS.md` remains the canonical tool-neutral protocol.
2. `CLAUDE.md` should be a thin adapter that imports `AGENTS.md`.
3. `.claude/skills` can mirror `.agents/skills`.
4. `.claude/rules` should be reserved for future path-scoped Claude-specific rules, not generated by default.

Sources:

1. https://code.claude.com/docs/en/memory
2. https://code.claude.com/docs/en/skills

### Cursor

Cursor supports project rules in `.cursor/rules/*.mdc` with metadata fields such as `description`, `globs`, and `alwaysApply`. Cursor also supports root `AGENTS.md` as a simpler alternative, but `.cursor/rules` gives better adapter visibility and control. `.cursorrules` is legacy and should not be generated.

Design implication:

1. `AGENTS.md` remains canonical.
2. `.cursor/rules/agent-feed.mdc` should be a thin Always rule that points Cursor to `AGENTS.md` and `.agents/`.
3. Cursor-specific rule content should not duplicate the full Agent Feed protocol.

Source:

1. https://docs.cursor.com/context/rules

### Mature CLI Patterns

Mature CLIs usually provide both guided interactive flows and deterministic flags:

1. Scaffolding CLIs such as `create-vite` prompt by default but allow project/template flags.
2. GitHub CLI exposes status/diagnostic commands such as `gh auth status` and supports machine-readable JSON in relevant places.
3. Typer and Click support command groups, options, prompts, generated help, and shell completion.
4. InquirerPy supports checkbox prompts suitable for arrow-key navigation and space-to-toggle multi-select.
5. Rich provides polished terminal output for panels, tables, progress, and structured diagnostics.

Design implication:

1. Interactive UX should be first-class for humans.
2. Flags must remain complete so scripts never depend on prompts.
3. `--json`, `--dry-run`, `-y`, `--no-input`, and predictable exit codes are product features, not polish.

Sources:

1. https://www.npmjs.com/package/create-vite
2. https://cli.github.com/manual/
3. https://typer.tiangolo.com/
4. https://click.palletsprojects.com/
5. https://inquirerpy.readthedocs.io/en/latest/pages/prompts/checkbox.html
6. https://rich.readthedocs.io/en/stable/introduction.html

## Product Contract

### Canonical Source Model

Agent Feed owns a tool-neutral canonical protocol:

```text
AGENTS.md
.agents/
  README.md
  rules/
  project/
  domain/
  session-state/
  skills/
  scripts/
  agents/
```

Client adapters are generated from that source:

```text
CLAUDE.md                  # Claude adapter importing AGENTS.md
.claude/skills/            # Claude project skill mirror
.cursor/rules/agent-feed.mdc
```

Codex does not need a project-local mirror because `AGENTS.md` and `.agents/skills` are already native Codex inputs.

### Client Adapter Responsibilities

| Client | Generated by default when selected | Source of truth | Notes |
| --- | --- | --- | --- |
| Codex | Nothing extra beyond `AGENTS.md` and `.agents/` | `AGENTS.md`, `.agents/skills` | Check only; no `.codex/skills` mirror by default |
| Claude | `CLAUDE.md`, `.claude/skills/` | `AGENTS.md`, `.agents/skills` | `CLAUDE.md` imports `@AGENTS.md` |
| Cursor | `.cursor/rules/agent-feed.mdc` | `AGENTS.md`, `.agents/` | Always rule, no `.cursorrules` |

### CLI Commands

The next public command set should be:

```sh
agent-feed
agent-feed init [path]
agent-feed sync [path]
agent-feed index-skills [path]
agent-feed skill-hub [path]
agent-feed check [path]
agent-feed status [path]
agent-feed preview [path]
agent-feed upgrade [path]
agent-feed config get [KEY] [--path PATH] [--json]
agent-feed config set KEY VALUE [--path PATH] [--dry-run]
agent-feed env status [path]
agent-feed env setup [path]
agent-feed env print
agent-feed env uninstall
agent-feed --version
```

Compatibility aliases:

```sh
agent-feed i       # init
agent-feed c       # check
agent-feed s       # sync
agent-feed sync-skills
```

Recommended common options:

```sh
--clients codex,claude,cursor|all|none
--checks structure,skills,references,session,codex,claude,cursor|all
--profile python|node|custom|none
--dry-run
-y
--no-input
--force
--force-generated
--json
--plain
--no-color
```

Verification profile command ownership:

1. Built-in `python`, `node`, and `none` profiles render deterministic generated behavior.
2. `custom` renders a generated verifier that sources `.agents/project/verification-commands.sh`.
3. Users should edit `.agents/project/verification-commands.sh`, not `.agents/scripts/verify-agent-dev.sh`, when they need custom project commands.
4. `code` and `full` scopes must fail until `run_project_code_checks()` is configured.

Public skill import ownership:

1. `skill-hub` searches only a curated registry of reviewed public repositories.
2. Imported skills default to `trust: custom`, even when upstream metadata says otherwise.
3. Install previews show the source link and file tree before any write.
4. Import never executes remote scripts; it only downloads files.
5. Successful import automatically runs the equivalent of `index-skills`.

### Command Behavior

#### `agent-feed`

No arguments should show a Rich-powered main menu in an interactive TTY:

1. Initialize this project.
2. Sync client adapters.
3. Check protocol health.
4. Show status.
5. Preview generated files.
6. Uninstall managed project assets.

In a non-TTY environment, it should print help and exit `0`.

#### `agent-feed init [path]`

Purpose: install canonical Agent Feed protocol assets and selected client adapters.

If `AGENT_FEED_HOME` is missing in an interactive run, prompt the user to run environment setup immediately. When accepted, create the external Agent Feed home, persist `AGENT_FEED_HOME`, set it for the current process, then continue init. Non-interactive init must fail with a clear remediation command instead of editing shell configuration silently.

Default Agent Feed home:

1. macOS/Linux: `~/.agent-feed`
2. Windows: `%APPDATA%\agent-feed`

The default Agent Feed home must be user-level and independent of the CLI installation directory. It must not live under a `uv tool` cache, wheel install directory, source checkout, or target project.

Interactive fields:

1. Target path.
2. Project display name.
3. Client adapters using checkbox multi-select:
   - Codex: `AGENTS.md` + `.agents/skills`
   - Claude: `CLAUDE.md` + `.claude/skills`
   - Cursor: `.cursor/rules/agent-feed.mdc`
4. Initial verification profile.

If `-y` is present, init must skip prompts and use default non-profile choices. It still requires an explicit `--profile` because choosing the wrong verification profile changes later AI development behavior.

For `--profile custom`, generated projects include `.agents/project/verification-commands.sh`. The file belongs to the project customization layer so users can add real commands without fighting template upgrades.

Non-interactive examples:

```sh
agent-feed init
agent-feed init . --clients all --profile python -y
agent-feed init ../repo --project-name "Billing API" --clients claude,cursor
agent-feed init . --clients none --profile none --dry-run
```

Collision policy:

1. Never merge into existing non-empty `.agents/`.
2. Never overwrite existing `AGENTS.md` or `CLAUDE.md` unless it is a managed Agent Feed adapter and `--force-generated` is used.
3. Generated adapters may be updated when managed markers match.
4. Unmanaged client files require a stop with actionable options.

#### `agent-feed sync [path]`

Purpose: regenerate selected client adapters from canonical assets.

Interactive fields:

1. Client checkbox multi-select.
2. Dry-run or write.
3. Force generated adapters only.

Behavior:

1. Codex: verify native assets exist; no extra write.
2. Claude: write/update managed `CLAUDE.md` and `.claude/skills`.
3. Cursor: write/update `.cursor/rules/agent-feed.mdc`.
4. Report unmanaged conflicts and exact next command.

#### `agent-feed index-skills [path]`

Purpose: regenerate `.agents/skills/README.md` from `.agents/skills/*/SKILL.md` frontmatter, add default metadata for imported skills, and maintain the machine-readable asset trust state in `$AGENT_FEED_HOME/config.json` outside the target project.

Behavior:

1. Fails if `.agents/skills` is missing.
2. Adds missing `source: unknow` and `trust: custom` to skill frontmatter.
3. Writes `.agents/skills/README.md`.
4. Refuses changed skill or managed-script hashes unless the user accepts them with `-y`.
5. Supports `--dry-run`.
6. Does not fetch external skills or execute skill-provided commands.
7. Leaves client adapter sync to `agent-feed sync`.

#### `agent-feed env uninstall`

Purpose: remove the user-level Agent Feed environment binding and optionally remove the user-level Agent Feed home.

Behavior:

1. Removes the managed shell block from zsh, bash, or fish config when present.
2. Removes the Windows user environment variable when running on Windows PowerShell.
3. Requires `--remove-home` before deleting the user-level Agent Feed home.
4. Deletes the home only when it contains a valid Agent Feed `config.json` or legacy `agent-feed.json`.
5. Supports `--dry-run` and requires `-y` in non-interactive cleanup.

#### `agent-feed uninstall [path]`

Purpose: remove Agent Feed-managed assets from one target project without deleting unmanaged user files.

Behavior:

1. Removes only managed project files and generated adapters.
2. Skips unmanaged `AGENTS.md`, `.agents`, Claude files, Cursor rules, or legacy mirrors.
3. Removes the target project's entry from `$AGENT_FEED_HOME/config.json`.
4. Does not remove the global/user-level Agent Feed home; use `agent-feed env uninstall --remove-home -y` for that.

#### `agent-feed upgrade [path]`

Purpose: refresh installed Agent Feed assets from the bundled standard template.

Behavior:

1. Require an existing `AGENTS.md` and `.agents/` installation.
2. Infer project name and verification profile from `.agents/agent-feed.json` when present.
3. Fall back to the `AGENTS.md` heading and generated verification script when metadata is missing.
4. Create missing template files.
5. Update changed managed reusable assets such as `AGENTS.md`, `.agents/README.md`, `.agents/rules/`, `.agents/skills/`, `.agents/scripts/`, `.agents/agents/`, and `.agents/session-state/README.md`.
6. Skip existing `.agents/project/` and `.agents/domain/` files because they are user-maintained.
7. Do not delete files.
8. Update selected client adapters non-destructively. Exact pruning remains a `sync --force-generated` concern.
9. Show the Changes table first. Diff details are opt-in with a single `v` keypress in interactive terminals or with `--diff` in scripts. Do not show a follow-up options menu.
10. Do not compare existing project/domain template files during upgrade or preview. They are user-maintained and should not produce persistent-drift noise.

#### `agent-feed config get [KEY]`

Purpose: read the whole project-visible `.agents/agent-feed.json` config or one dotted key.

Behavior:

1. Require an installed Agent Feed project.
2. Support dotted keys such as `verification_profile` and `settings.session_state.max_carry_forwards`.
3. Support `--json` for machine-readable output.

#### `agent-feed config set KEY VALUE`

Purpose: update one project-visible `.agents/agent-feed.json` value and immediately refresh the managed outputs derived from project config.

Behavior:

1. Require an installed Agent Feed project.
2. Allow mutable keys only: `project_name`, `verification_profile`, and `settings.*`.
3. Parse JSON values when possible, while preserving plain strings.
4. Preserve user-level secrets and accepted hashes in `$AGENT_FEED_HOME/config.json`; do not copy them into the project.
5. Regenerate settings-driven managed files such as `.agents/agent-feed.json`, `.agents/session-state/schema.json`, skill metadata defaults, `.agents/skills/README.md`, and configured client adapters.
6. Update external trust state after skill metadata changes.
7. Support `--dry-run` for the config-file write preview.

#### `agent-feed check [path]`

Purpose: validate current protocol health.

Interactive checks:

1. `structure`: required files and directories.
2. `skills`: skill names, required frontmatter, trust values, and generated skill index freshness.
3. `references`: markdown `.agents/` links and README indexes.
4. `session`: session-state JSON shape.
5. `codex`: native Codex readiness.
6. `claude`: `CLAUDE.md` import and `.claude/skills` mirror.
7. `cursor`: `.cursor/rules/agent-feed.mdc` frontmatter and managed content.
8. `scripts`: generated script existence and executable mode.

Exit codes:

1. `0`: all selected checks pass.
2. `1`: selected checks ran and found failures.
3. `2`: invalid CLI usage.
4. `3`: unsafe unmanaged conflict blocked a write/fix.

#### `agent-feed status [path]`

Purpose: concise installed-project Changes table plus JSON health dashboard.

Output:

1. Compact Changes table for managed template, adapter, and trust drift.
2. Press `v` in a TTY to open the full `preview` diff view.
3. JSON mode keeps the machine-readable health dashboard for automation.

Support `--json`.

#### `agent-feed preview [path]`

Purpose: show the write plan before `init`, or upgrade diffs for an installed project.

Output:

1. Files to create.
2. Files to update.
3. Diff availability for changed installed files.
4. Files blocked by unmanaged content.
5. Files unchanged.

If the target does not have Agent Feed installed, `preview` shows the init write plan. If the target has `AGENTS.md` and `.agents/`, `preview` shows full red/green diffs directly. Use `status` for the compact Changes table. Installed-project preview should default to currently configured clients; pass `--clients all` only when the user wants to inspect additional adapter writes. If `.agents/agent-feed.json` is missing or has an older version, include its creation/update in the change plan.

#### `agent-feed skill-hub [path]`

Purpose: search curated public skill hubs, preview selected skills, then install
them into `.agents/skills`.

Behavior:

1. Search only the built-in allowlist registry.
2. Match skills by keyword against the skill name, description, and hub name.
3. In TTY mode, show a checkbox list where `Space` selects, `v` previews, `Enter`
   installs, and `Esc` goes back or cancels.
4. Preview the source URL and target file tree before any write.
5. Install imported skills as `trust: custom` and `source: hub:<registry-key>`.
6. Never execute remote scripts during import.
7. Automatically run the equivalent of `index-skills` after a successful install.
8. Support `GITHUB_TOKEN` and a user-level `~/.agent-feed/config.json` `settings.github_token` value so GitHub API rate limits do not make the feature unreliable.

### Command Boundary Review

The current command set is useful but has overlap:

1. `check`: health validation and exit codes.
2. `status`: compact human Changes table and JSON health dashboard.
3. `preview`: dry-run init/upgrade view.
4. `upgrade --dry-run`: dry-run upgrade view with the same installed-project diff purpose as `preview`.
5. `sync`: exact generated adapter regeneration.
6. `index-skills`: canonical skill discovery index regeneration, intentionally separate from adapter sync.
7. `skill-hub`: external skill import, intentionally separate from registry-free manual `index-skills`.

Recommended current stance:

1. Remove `doctor`; it duplicated `check` without owning sync.
2. Treat `preview` as the user-friendly dry-run entry.
3. Treat `upgrade --dry-run` as script-friendly parity.
4. Keep repair ownership narrow: `sync` repairs generated adapters, `upgrade`
   refreshes canonical assets, and `index-skills` updates skill metadata/trust.
5. Review further consolidation before a stable public release, not during protocol hardening.

## Interactive UX

Use Rich for:

1. Welcome panel.
2. Command summary table.
3. Status tables.
4. Error panels with next actions.
5. Dry-run write plan.
6. Unified diffs with green additions, red deletions, cyan hunk headers, and bold file headers.

Use InquirerPy for:

1. Client checkbox multi-select.
2. Check-category checkbox multi-select.
3. Profile select.
4. Confirm prompts.

Keyboard behavior:

1. Up/down moves selection.
2. Space toggles checkbox.
3. In `skill-hub`, `v` previews the highlighted skill.
4. Enter confirms.
5. Ctrl-C exits with code `130`.

Non-TTY behavior:

1. Never prompt.
2. `-y` confirms write operations and skips prompts by using explicit flags or defaults.
3. Otherwise fail with a message that lists the required flags.

Help and output conventions:

1. Primary help should show the commands users are expected to run, not framework plumbing.
2. `-h` and `--help` are supported everywhere.
3. Typer shell-completion helper flags are intentionally not exposed in the main help while the public command surface is still pre-release.
4. `agent-feed` without arguments should give humans a guided entrypoint, while concrete subcommands remain the stable automation interface.
5. Diff previews must be scannable before write operations; color is semantic, not decorative.
6. Tables should group status and diagnostics by area so users can identify the blocked layer before reading individual messages.

## Managed File Markers

Generated adapters should include a stable marker:

```text
<!-- agent-feed:managed adapter=claude version=1 -->
```

For Cursor MDC:

```md
---
description: Agent Feed AI development protocol
alwaysApply: true
agentFeedManaged: true
agentFeedVersion: 1
---
```

Rules:

1. Managed files may be updated by `sync`.
2. Unmanaged files stop writes.
3. `--force-generated` only overwrites managed generated files; it does not overwrite user-owned files.

## Tests And Verification

Minimum tests before implementation is considered done:

1. `init` creates canonical assets in cwd when path is omitted.
2. `init --clients all` creates Claude and Cursor adapters but no `.codex/skills`.
3. `sync --clients claude,cursor` updates only managed adapter files.
4. `sync --clients codex` performs checks and writes nothing extra.
5. `check --checks codex,claude,cursor` detects missing and stale adapters.
6. `status --json` returns stable machine-readable output.
7. Imported or local skills always remain lower priority than built-in rules and do not gain trusted status automatically.
8. Interactive prompts are covered through prompt abstraction tests, not brittle terminal snapshots.
9. Build output contains only package files and templates intended for PyPI.

Verification commands:

```sh
uv run ruff check src
uv run mypy src
uv run pytest
uv run agent-feed check . --checks all
sh .agents/scripts/verify-agent-dev.sh docs
uv build
```

## Development Plan

### Phase 1: Dependencies And CLI Framework

Decision required before implementation:

1. Add `typer`, `rich`, and `InquirerPy`.
2. Keep current `argparse` and only add `rich` + `InquirerPy`.

Recommendation: use Typer + Rich + InquirerPy because command growth, help output, shell completion, typed options, and interactive prompts are now core product requirements.

Deliverables:

1. Update `pyproject.toml`.
2. Introduce `console.py`, `prompts.py`, `models.py`.
3. Preserve current command behavior through compatibility aliases.

### Phase 2: Adapter Contract

Deliverables:

1. Implement Codex native adapter checks.
2. Implement Claude adapter generation: `CLAUDE.md` and `.claude/skills`.
3. Implement Cursor adapter generation: `.cursor/rules/agent-feed.mdc`.
4. Remove `.codex/skills` from default generated targets.

### Phase 3: Check, Status, Skill Hub

Deliverables:

1. Split check categories into modules.
2. Add structured `CheckResult`.
3. Add `status` human and JSON output.
4. Add curated public skill import with a strict allowlist and preview-first install path.

### Phase 4: Interactive UX

Deliverables:

1. Main menu for `agent-feed`.
2. Checkbox clients for init/sync.
3. Checkbox checks for `check` and checkbox selection for `skill-hub`.
4. Plain output fallback.
5. Non-TTY no-prompt guard.

### Phase 5: Documentation And Verification

Deliverables:

1. Update `README.md`.
2. Update `docs/product-design.md`.
3. Update `docs/template-model.md`.
4. Add CLI examples and screenshots later if needed.
5. Run full verification gate.

## Confirmed Decisions

Confirmed on 2026-04-30:

1. Use Typer + Rich + InquirerPy.
2. Do not generate `.codex/skills`; use native `AGENTS.md` and `.agents/skills`.
3. Generate root `CLAUDE.md` with `@AGENTS.md`, plus `.claude/skills`.
4. Generate `.cursor/rules/agent-feed.mdc` as an Always rule; do not generate `.cursorrules`.
5. Add `status`, `skill-hub`, `preview`, and short aliases.
6. Keep docs out of the PyPI package unless later publishing documentation as project metadata.
